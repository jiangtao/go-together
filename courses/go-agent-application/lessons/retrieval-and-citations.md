# Day 5：一次问答中的检索与引用

返回：[课程目录](../README.md)

## 学习目标

- 回答看起来合理，不代表它使用了正确文档。本课从引用反向核对检索和生成依据。
- 能够区分检索不到、排序错误、上下文丢失和生成无依据，而不是统一称为“模型不行”。
- 两个问题的检索/回答/引用对照及 Go 结果组装位置。

## 先修与边界

先完成 Day 4 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

从熟悉的页面请求、异步状态和错误处理出发；在 Go 中额外追踪显式 error、context 传播、接口边界与数据所有者。

## 原理与机制

检索选择候选片段，排序影响进入上下文的顺序，模型基于最终上下文生成文本，页面再展示引用。每层可能裁剪或改写数据。引用应能回到具体文档和片段，不能仅凭标题相同判定来源正确。

## 动手步骤

1. 在测试知识库放入两份名称相似但事实不同的短文档。
2. 提出只在其中一份文档出现的问题，保存候选片段、最终上下文的可观察摘要和页面引用。
3. 从返回数据找到文档/片段身份及相关分数字段，追到 Go 中组装结果的位置。
4. 核对文档事实、检索片段、回答陈述和引用目标是否对应。
5. 再问一个资料中没有答案的问题，记录模型和页面如何表达缺少依据。

## 观察与产出

能够区分检索不到、排序错误、上下文丢失和生成无依据，而不是统一称为“模型不行”。

交付：两个问题的检索/回答/引用对照及 Go 结果组装位置。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。

## 验证方式

记录真实浏览器请求与 Go 后端结果；环境、模型或依赖缺失时明确标记尚未完成，不以源码阅读替代本课运行证据。

## 检索问题

- 为什么不能直接比较不同检索器的原始分数？
- 有引用但回答内容超出原文，能否算有依据？

## 常见误区

把任意非空引用当作答案正确；忽略版本、片段身份与实际支持关系。
