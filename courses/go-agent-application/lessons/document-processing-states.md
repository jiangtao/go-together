# Day 4：解析、切分与索引的状态边界

返回：[课程目录](../README.md)

## 学习目标

- 文档已经出现在列表里，却没有检索结果时，必须知道它卡在哪个处理阶段。
- 能定位文档停在哪一步，并解释页面状态与后端事实之间的映射。
- 处理状态图、一份片段样例和一个失败/恢复场景。

## 先修与边界

先完成 Day 3 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

从熟悉的页面请求、异步状态和错误处理出发；在 Go 中额外追踪显式 error、context 传播、接口边界与数据所有者。

## 原理与机制

解析把格式转成文本，切分把文本组织成可检索片段，索引让片段可被查询。每步都有输入、输出、失败和重试边界。页面显示的一个状态可能聚合多个后台阶段，不能从 UI 文案猜数据库状态。

## 动手步骤

1. 沿上传后产生的文档或任务身份定位处理入口和状态字段。
2. 依次记录解析、切分、索引的调用点及其输入输出；若当前版本采用不同组织，按实际实现绘图。
3. 用含两个标题和多段正文的测试文档观察片段边界，保留文段与来源身份。
4. 在本地测试中选择一个可控失败点，例如解析失败或索引适配器返回错误。
5. 记录失败如何进入存储和页面，恢复依赖后是否自动重试、重新提交或人工触发。

## 观察与产出

能定位文档停在哪一步，并解释页面状态与后端事实之间的映射。

交付：处理状态图、一份片段样例和一个失败/恢复场景。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。

## 验证方式

记录真实浏览器请求与 Go 后端结果；环境、模型或依赖缺失时明确标记尚未完成，不以源码阅读替代本课运行证据。

## 检索问题

- 解析成功、索引失败时，应保留哪些事实？
- 重新切分后旧片段的引用身份可能受到什么影响？

## 常见误区

把“上传成功”作为索引成功的证据，或者直接删除失败记录掩盖状态问题。
