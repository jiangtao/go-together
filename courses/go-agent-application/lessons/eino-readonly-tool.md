# Day 23：一个只读业务工具的契约

返回：[课程目录](../README.md)

## 学习目标

- 复用已熟悉的查询问题，关注工具参数、执行和结果反馈。
- 工具只做约定查询，业务层不依赖整个 Agent SDK；至少覆盖四种输入/结果边界。
- 一个工具适配器、输入矩阵与取消/错误测试。

## 先修与边界

先完成 Day 22 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

工具 schema 描述模型可以提交的输入，业务校验仍必须在服务端执行。名称是稳定路由键，描述是选择依据；成功空结果、业务不存在和调用失败需要保留区别。

## 动手步骤

1. 优先复用基础课 Day 30 的 Trip 查询、fake store 与输入矩阵，不重写已有业务逻辑；没有既有产物时再准备最小查询及存在、不存在、依赖失败数据。
2. 用当前 Eino 版本的工具入口适配 service，明确输入字段与必要约束。
3. 验证缺失、格式错误和合法 ID，不把 schema 当成唯一校验。
4. 用脚本模型触发工具，核对工具调用 ID、参数、结果和下一轮消息。
5. 将 ctx 传入业务层，用阻塞替身证明工具响应取消。

## 观察与产出
