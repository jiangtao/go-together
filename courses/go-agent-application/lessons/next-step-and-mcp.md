# Day 30：复盘与按需 MCP 接入

返回：[课程目录](../README.md)

## 学习目标

- 按既定路线结束这一轮：继续 WeKnora 与 Eino，只有实际工具接入需求才进入 MCP。
- 不要求实现 MCP 才能完成本课；必须有基于实际需求的判断与下一目标。
- 学习复盘、一个后续目标与 MCP 是否需要的判断依据。

## 先修与边界

先完成 Day 29 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

MCP 是工具接入协议，不替代业务逻辑、Agent 决策和权限判断。本地函数已经满足需求时，增加协议会带来传输、会话和错误映射成本。需要跨进程复用工具时，再比较 SDK 与传输方式。

## 动手步骤

1. 总结从页面现象追到 Go 后端的一个完整案例，以及自己修复或验证过的一个边界问题。
2. 解释 Eino 小服务如何帮助理解上下文、工具循环和流式返回。
3. 写出一个下一步真实需求；若只是补齐主项目能力，继续对应课题。
4. 仅当需求需要跨进程工具接入时，选择官方 Go SDK 或 MCP-Go 之一，先设计一个只读工具的发现、调用、错误和取消契约。
5. MCP 选修验证应包括本地 client/server 一次调用和资源回收；没有接入需求时明确说明暂不引入的依据。

## 检索问题

- 本地函数与 MCP 工具的责任边界有何不同？

## 常见误区
