## 原理与机制

至少一次投递意味着同一任务可能再次执行。幂等不是“永远执行一次”，而是在重复触发时保持业务结果正确。重试需要区分暂时性依赖失败、永久参数错误和用户取消，并有次数或时间边界。

## 动手步骤

1. 定位一个文档任务的入队、消费、成功确认和失败记录位置。
2. 记录任务身份、业务文档身份、重试次数和去重依据是否不同。
3. 用本地替身模拟首次暂时失败、第二次成功，观察状态和副作用。
4. 再次提交同一业务操作，检查是否产生重复片段、索引或状态回退。
5. 列出无法重试与可以重试的错误，核对实现中的退避和上限；缺少机制时只记录事实。
