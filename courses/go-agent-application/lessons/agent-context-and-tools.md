# Day 14：上下文构建与工具选择

返回：[课程目录](../README.md)

## 学习目标

- 同一问题在普通问答与 Agent 模式中可能经过不同处理。用实际输入输出理解选择依据。
- 每个模式都有实际源码路径；不能默认 WeKnora 使用 Eino 或共享同一套循环。
- 两种模式的对比、一条工具链和上下文来源表。

## 先修与边界

先完成 Day 13 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

从熟悉的页面请求、异步状态和错误处理出发；在 Go 中额外追踪显式 error、context 传播、接口边界与数据所有者。

## 原理与机制

模型看到的是组装后的上下文，不是数据库中全部历史。系统指令、用户输入、检索片段、工具定义和工具结果具有不同来源。工具选择需要可理解的名称、参数约束和结果反馈；工具返回成功也不等于任务已完成。

## 动手步骤

1. 用同一个测试问题分别观察普通问答与 Agent 模式，记录实际参与步骤。
2. 定位 Go 中构建模型消息、加入检索结果与注册工具的位置。
3. 记录上下文的来源、顺序、裁剪规则和关联身份，只保存脱敏摘要。
4. 选择一次真实发生的工具调用，追踪参数校验、业务执行和结果回填。
5. 对一个错误答案判断模型是否看到了关键证据，区分上下文遗漏与生成判断错误。

## 观察与产出

每个模式都有实际源码路径；不能默认 WeKnora 使用 Eino 或共享同一套循环。

交付：两种模式的对比、一条工具链和上下文来源表。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。

## 验证方式

检查每项产物的版本、源码位置与判断依据。本课不要求为了形式运行不相关的测试；引用前课验证时必须指明具体行为和结果。

## 检索问题

- 检索命中正确但回答错误，接下来应核对哪一步？
- 工具结果与最终回答为什么需要分开存储或关联？

## 常见误区

只调 prompt，却没有核对模型实际收到的内容。
