## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

最大步数限制推理循环长度，超时限制时间，错误分类决定继续还是退出。可反馈给模型的业务失败与运行级失败不同。取消之后继续把错误作为 observation 重试，会违背调用方停止意图。

## 动手步骤

1. 配置或实现当前运行入口支持的循环上限，明确“步”如何计数。
2. 脚本化直接回答、工具后回答、未知工具、工具业务失败和模型失败。
3. 让模型持续请求工具，断言上限触发后不再调用模型或工具。
4. 在模型等待、工具等待和两轮之间分别触发取消，核对退出行为。
5. 整理错误到事件/HTTP 边界的映射，终态只能形成一次。

## 观察与产出

每条失败路径都能有界退出，取消不被包装成正常成功。

交付：终止条件表、持续调用测试与错误/取消回归。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。

## 检索问题

- 只设置每次模型调用超时，能否限制整个 run 的总时长？
- 哪些错误适合作为 observation，哪些必须终止运行？

## 常见误区

捕获全部错误后继续循环，导致无限重试或错误答案。
