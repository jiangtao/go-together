# Go Agent 学习与贡献计划

> 2026-09-15。状态：已落地为 `go-agent-application` 的 30 篇课文与线路图节点。依据指定调研会话在补充个人背景后的最终结论；课文完成不代表学习者已完成实验、部署或上游贡献。

## 1. 已确定的方向

学习者背景：**前端应用侧转来，有一定 Node.js 后端基础，希望进入 Go 后端与 Agent，并能深入和参与 Issue 贡献。**

沿用调研的最终建议：**WeKnora 学完整应用和做首次贡献 → Eino 深入 Agent 机制 → 有实际接入需求时再学 MCP。**

WeKnora 是主项目，Eino 是第二阶段。此前面向泛 Go 后端开发者的 Eino/MCP-Go 优先建议已被针对上述背景的建议取代。MCP-Go、官方 MCP SDK 和 PicoClaw 均不作为必经阶段。后续修改先核对这一结论，不能重新套用早期榜单的学习顺序。

本计划只细化练习、产物和验收方式，不重新选型。学习网站的 Go 课程阶段、阅读课与复盘课应与此顺序一致。

## 2. 从熟悉的应用问题逐层深入

WeKnora 的官方资料包含知识库、检索、Agent 和 Go 后端能力，适合沿实际用户操作进入。[官方 README](https://github.com/Tencent/WeKnora)

贯穿链路：**上传文档 → 解析与切分 → 建立索引 → 用户提问 → 检索 → Agent 调用工具 → 流式返回。**

这是一条教学调查路径；具体模式中哪些步骤参与执行，要回到所选版本的代码核实。例如普通问答与 Agent 模式不应默认共用完全相同的调用链。

| 深度 | 研究内容 | 必须拿出的证据 |
|---|---|---|
| 第一层：功能闭环 | 页面操作、请求参数、Go 路由、校验、错误和流式展示 | 至少一次浏览器操作与 Go 业务处理的对应关系，附代码位置和请求结果 |
| 第二层：后端机制 | 异步任务、超时取消、重试、数据一致性、并发限制 | 一个边界问题的复现、关键 Go 测试及解释 |
| 第三层：Agent 与检索 | 上下文构建、工具选择、检索排序、引用、质量评估 | 一组固定问题与来源，解释失败发生在哪一步 |

**每个学习任务至少追到一段 Go 业务逻辑，并为关键行为补上验证。** 页面样式或交互调整不能单独作为后端学习完成的证据。

## 3. 与现有 Go 课程衔接

既有 36 天课程提供基础材料，WeKnora 提供真实问题。进入应用链路前先能看懂 handler、JSON DTO、error、context 和基本测试；其余主题根据实际遇到的问题补齐。学习者是否通过原课程仍由原评测规则决定。

基础课的 Agent 切片保留为 Go 综合练习，不扩展成框架课。实战课复用 Trip 查询、fake store、模型脚本、业务事件和测试场景，新增真实项目行为与 Eino 边界验证；不重写同样的业务代码，不自动继承评测通过状态。

| 已有课程材料 | 在 WeKnora 中回答的问题 |
|---|---|
| Day 1-6：Go 心智、数据结构、error/interface/context | 参数和零值怎么表达？错误如何保留？取消如何跨调用传播？ |
| Day 7-10：HTTP、JSON、测试 | 页面字段落到哪个 handler/service？错误为什么显示不完整？ |
| Day 11-16：数据库与事务 | 文档状态、索引状态与任务状态如何保持一致？先核对项目实际数据层，不假定使用 sqlc |
| Day 21-28：流式、并发、运行治理 | 用户取消、连接断开、重试与 shutdown 后，后台任务是否继续？ |
| Day 29：开源阅读 | 围绕 WeKnora 一条请求做四遍阅读，记录真实源码位置 |
| Day 30-36：最小 Agent 与复盘 | 用课程 Trip 切片辅助拆解机制；在第二阶段与 Eino 小服务比较 |

gRPC 与特定数据工具按所读模块需要补齐，不把学完所有工具设为打开主项目的前提。gRPC 解决服务之间的调用契约，Eino 解决服务内部的 Agent 执行；前者不是后者的先修要求。Eino 小服务先用 HTTP，复用已掌握的 context、错误与流式测试，只验证新增的 Agent 边界。练习不得把 WeKnora 强行改造成课程的目录或技术栈。

## 4. 第一项深入练习：取消回答

调查问题：**用户取消回答后，页面停止显示，后端是否也停止调用模型并释放资源？** 这是待验证的问题，不预设 WeKnora 存在缺陷。

1. 固定项目版本，在测试知识库中触发一次持续回答，记录请求和操作时点。
2. 观察页面取消究竟发送显式请求、终止流连接，还是只改变页面状态。
3. 定位 Go handler、任务/会话管理、模型或工具调用中的 context 来源和传播位置。
4. 区分客户端离开、显式取消、服务端超时和后台任务的既有语义；不能一概认定断连就必须取消持久任务。
5. 使用阻塞的模型/工具替身与同步信号，验证预期的取消、终态和清理行为；不靠长 sleep 猜测。
6. 对照浏览器现象与 Go 测试结果。若行为符合项目契约，记录理解；若不一致，再找 Issue/PR 并判断修复范围。

完成标准：能解释完整取消路径；有一项 Go 行为验证；明确哪些资源已释放、哪些属于独立后台任务。源码推断、fake 测试和真实模型行为分别记录。

## 5. 分阶段计划

以下 30 个学习单元已对应独立课程的 Day 1-30，稳定 Lesson ID 与课文见 [课程目录](../courses/go-agent-application/README.md)。每单元预计 60-120 分钟，总量约 30-60 小时；部署排障和环境准备可能额外耗时。新课与基础课分别记录进度，以阶段产物验收，不按日期强行推进。

线路图采用“课程 → 三条主干 → 五个阶段 → 课次”的分层结构：WeKnora 应用与后端包含阶段 A/B，真实项目贡献包含阶段 C，Agent 机制与复盘包含阶段 D/E。主干横向分块以便总结，阶段保留递进和里程碑；Day 8、16、20、28、30 分别汇总阶段产物。推进连线表示建议路径，不把展示分组等同于强制依赖。

### 阶段 A：WeKnora 功能闭环

| 单元 | 学习动作 | 产物与完成条件 |
|---|---|---|
| P01 | 固定版本，核对官方启动方式、Go 工具链和必需依赖 | 版本/镜像/tag/SHA 与环境清单；缺失项明确，不猜可用组合 |
| P02 | 启动本地最小环境，一个知识库、一个可用模型配置 | 浏览器与后端健康证据；资源或模型不可用时标记阻塞 |
| P03 | 上传一份小文档，观察处理状态 | 上传请求到 Go handler/service 的对应表 |
| P04 | 跟踪解析、切分与索引处理 | 状态变化和数据位置；注明同步/异步边界 |
| P05 | 提一个答案明确的问题，查看检索与引用 | 问题、命中文段、返回内容与页面引用对应关系 |
| P06 | 追踪问答接口与流式展示 | 5-8 个关键函数/类型节点，至少包含 Go 业务层 |
| P07 | 比较参数正确、非法与缺失的响应 | 至少一项 Go 校验测试与页面错误结果 |
| P08 | 闭卷复述上传与问答两条链 | 阶段 A 验收：能独立从用户操作追到 Go 业务逻辑 |

### 阶段 B：WeKnora 后端机制与检索

| 单元 | 学习动作 | 产物与完成条件 |
|---|---|---|
| P09 | 按上一节调查取消回答 | 明确实际语义与 context 路径；不预设 bug |
| P10 | 验证模型/工具阻塞后的取消 | Go 测试证明退出或明确后台任务边界 |
| P11 | 选择一个异步文档任务，追踪失败和重试 | 状态转换、重试触发与重复处理边界 |
| P12 | 核对任务状态与数据库/索引一致性 | 一次局部失败的验证，解释谁负责修复状态 |
| P13 | 阅读一个并发限制或超时控制点 | 配置如何生效、测试覆盖什么；没有机制时记录事实 |
| P14 | 追踪上下文构建和工具选择 | 普通问答与 Agent 模式的实际差异，附源码证据 |
| P15 | 用固定问题观察检索排序与引用 | 10 份小文档、10 个问题，包含无答案场景与预期来源 |
| P16 | 对失败问题逐层归因 | 阶段 B 验收：区分解析、检索、排序、上下文、工具与生成失败 |

### 阶段 C：WeKnora 首次贡献

| 单元 | 学习动作 | 产物与完成条件 |
|---|---|---|
| P17 | 从已观察现象筛选最多三个小问题，查评论和关联 PR | 候选表说明是否可复现、是否有人处理、Go 改动范围 |
| P18 | 只选一个前后端交界问题，最小复现 | 固定版本、输入、预期/实际结果与稳定失败测试 |
| P19 | 做最小修复，或验证已有修复 | 同一测试的前后结果，邻近行为不回归 |
| P20 | 整理本地贡献材料 | 阶段 C 验收：复现、Go 证据、补丁/验证与限制齐全，发布单独授权 |

优先选题沿用调研结论：页面参数在后端未生效；取消/重试/刷新后的状态不一致；错误信息丢失；流式结束、异常或断连的处理；检索分数、来源与引用展示不一致。这些是选题方向，不代表已经确认且无人处理的 Issue。

历史调研中的检索分数问题已有修复参与者，只能作为阅读或补充验证线索。开始贡献时重新检查状态；未分派不等于无人处理。找不到合适的新问题时，验证已有 PR 或补充有效测试也算成果，不能制造重复修复。首次贡献继续围绕 WeKnora，不为追求小 PR 临时换主项目。

### 阶段 D：Eino 深入 Agent 机制

进入条件沿用调研结论：**能独立追踪 WeKnora 一次问答请求。** 上游是否合并贡献不影响进入这一阶段。

| 单元 | 学习动作 | 产物与完成条件 |
|---|---|---|
| P21 | 从已理解的应用行为抽出 HTTP → 单 Agent → 一个业务工具 → 流式返回 | 明确小服务输入、输出和边界；固定 Eino 版本 |
| P22 | 使用官方 ADK 入口与模型替身跑通一次调用 | 不依赖真实模型波动的确定性测试 |
| P23 | 接入一个只读工具，可复用 Trip 查询练习 | 参数校验、工具结果与 call ID 关联 |
| P24 | 处理直接回答、工具失败、模型失败和持续调用 | 最大步数、错误分类与测试证据 |
| P25 | 接回 HTTP 与流式事件 | event 到页面状态的映射；取消与终态可解释 |
| P26 | 比较小服务与 WeKnora 的上下文/工具组织 | 区分应用业务代码与框架职责，不假定 WeKnora 内部依赖 Eino |
| P27 | 选择上下文管理或中断恢复中的一个机制深入 | 固定版本源码与局部测试；持久化日志不等于执行检查点 |
| P28 | 复盘何时需要编排或多个 Agent | 阶段 D 验收：单 Agent 小服务可测，能解释机制与复杂度取舍 |

Eino 的模型、工具与 Runner 入口以[官方快速开始](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/agent_quickstart/)和所选版本为准。真实模型冒烟与 fake 回归分别记录；具体中断恢复 API 在实施时核对，不能照搬不同版本的示例。

### 阶段 E：复盘与按需 MCP

| 单元 | 学习动作 | 产物与完成条件 |
|---|---|---|
| P29 | 重跑本轮所改模块与链路验证 | 版本、命令、浏览器结果与环境缺口可复查 |
| P30 | 汇总应用到机制的学习证据，确定一个后续需求 | 有实际跨进程工具接入需求才安排 MCP，否则继续主项目 |

## 6. 验证与环境边界

| 验证层 | 要证明的内容 | 不能替代什么 |
|---|---|---|
| 浏览器链路 | 页面操作、请求、流式内容、引用和错误状态 | 页面停止不能单独证明 Go 任务已停止 |
| Go 单元/局部集成测试 | 参数、错误、取消、状态与回归行为 | fake 不等于真实模型或真实数据库验收 |
| 本地系统验证 | 实际文档处理、检索、模型调用和资源释放 | 源码阅读不等于已跑通系统 |
| 贡献材料 | 问题可复现，范围明确，修复或验证有证据 | PR 合并与维护者回复速度不是学习通过条件 |

从已连接且具备登录态的真实 Chrome 验证前端主链路。Go 检查先运行目标包，再按改动范围运行项目已有检查；不把下列示例当成未经核对的 WeKnora 全量测试方案：

```bash
go test ./path/to/changed/package
go test -race ./path/to/changed/package
```

执行前替换为实际包路径并确认目标模块。数据/模型依赖、迁移和集成测试按所选版本的官方文档及 CI 核实，仅使用本地测试数据。先记录基础测试是否本来失败，再区分本次回归。

版本固定、依赖下载、模型配置属于练习准备；既有课程评测配置关闭依赖网络访问，不为跑通练习临时放宽。付费调用、外部发言、提交 PR 和发布操作均需要对应授权。环境不足时明确阻塞，不自动用别的项目替换 WeKnora 主线。

学习证据记录单元、项目 SHA、源码位置、操作步骤、实际命令、关键断言与限制。新增课使用 `learning-records/go-agent-application/lessons/<lessonId>/`，基础课仍使用自己的课程域记录。准备与评测显式提供两项稳定身份，不代写答案或手写进度。

## 7. 教程与网站同步

基础课保留既有稳定 Lesson 身份，末阶段定位为“Go 综合练习与 Agent 入门”。Day 29 阅读目标与 Day 36 进阶内容保持 WeKnora → Eino → 按需 MCP；独立的“Go Agent 应用实战”以 3 条主干组织 5 个阶段和 30 个可阅读节点，各阶段说明显示里程碑。

每课包含学习目标、先修边界、Node.js 对照、原理、动手步骤、产物、验证方式、检索问题、误区与资料。学习者执行 P01-P08 时需要真实本地环境；课程不会把尚未进行的系统实验写成通过。课程源、Manifest、评测政策和命令配置共同定义完整内容。

课源修订后用仓库导出器从 Evaluation 派生公开快照，核对学习状态与分数。完成课程契约、公开生成、确定性、审计和浏览器检查后才报告网站验证结果；部署仍遵守仓库发布流程。
