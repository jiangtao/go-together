# Day 25：HTTP 与 Agent 事件流

返回：[课程目录](../README.md)

## 学习目标

- 让小服务把运行过程交给客户端，同时保持取消和终态一致。
- 断言业务事件而非网络 Read 次数；HTTP 200 之后的失败通过明确事件表达。
- HTTP/流式集成测试、事件映射与断连证据。

## 先修与边界

先完成 Day 24 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

模型 token、工具事件和业务进度不是同一种数据。服务应定义自己需要的事件并在适配层转换。HTTP 连接可能比后台任务更早结束，因此关闭责任、慢消费者和错误传播必须明确。

## 动手步骤

1. 选择一条 HTTP 入口，优先复用基础课的业务事件定义、SSE handler 与测试客户端；缺少时补最小实现，不为了新课程重写一套相同传输层。
2. 将 Eino 当前版本的运行事件转换成课程服务事件，保留 run 与 tool call 关联身份。
3. 用本地测试客户端消费完整回答，断言事件顺序允许的约束和唯一终态。
4. 模拟慢消费者与连接关闭，验证既定取消规则和资源回收。
5. 比较 WeKnora 的对应边界，记录小服务省略了哪些业务职责。

## 观察与产出

## 检索问题

- 为什么模型 token 不适合直接充当全部业务进度？
- 谁应负责关闭发送 channel 和响应流？

## 常见误区

写入失败后仍继续生成，或多处关闭同一个 channel。
