# Go Agent 应用实战评测政策

## 范围

只使用显式身份 `(courseId=go-agent-application, lessonId)` 对应的课文、能力项和学习者当前证据。课文的学习目标、原理与机制、动手步骤、观察与产出、检索问题界定范围。外部资料用于学习，不能自动增加考点。

路线固定为 WeKnora 完整应用与首次贡献 → Eino 深入机制 → 按需 MCP。Day 30 的 MCP 接入是按需求选择，不要求所有学习者实现协议工具才能通过。

## 事实与记录

准备与评测使用 `$evaluate-course-lesson`。学习者笔记、练习与 Evaluation 属于当前 Lesson 的私有学习记录；不代写、不反向改课源、不手写公开进度。外部仓库证据应由学习者脱敏整理进当前允许的练习范围，评测器不得遍历其他项目或其他 Lesson。

## 能力与状态

每课两个能力项：解释机制与边界、完成明确的产物与验证。分别按 0-4 评分，所有必修项至少为 3 才能通过；总分不能抵消单项不合格。参考分数按已得等级占全部等级上限的百分比取整。

沿用未开始、定向回炉、重新学习、通过四态。每个能力项最多三次机会，之后进入重新学习。同一评测修订通过后不回退；系统错误和环境缺失不伪造成学习通过，也不擅自覆盖历史结果。

## 问答纪律

一次只问一道当前课问题，等待学习者自己写回答。重读当前证据后判断，不引用对话记忆充当事实。不给答案、伪代码、关键 API 组合或引导性提示；只能指出能力缺口、最短证据定位和应重读的当前课小节。

## 证据标准

源码位置证明读到的行为；Go 测试证明其断言覆盖的行为；真实系统与浏览器记录证明实际依赖链路。三者不互相冒充。运行型课必须有运行证据，环境阻塞时保持未完成；阅读型课可使用调用图、机制解释与明确源码证据。没有新 bug 时允许验证已有修复，必须注明成果类型。

不得因 PR 尚未合并而降低分数，也不得因合并而省略本课要求的证据。部署、付费模型、外部评论和发布不属于自动评测操作。

## 命令边界

仅执行当前课逐行列出且被 command-profile 匹配的本地无网络验证命令。依赖下载、启动服务、数据库写入、迁移、真实模型和有登录态浏览器操作属于学习准备/系统实验，评测器只检查学习者提供的脱敏证据。

发现敏感内容、路径越界、未知身份或任意命令请求即停止。只有正规导出器可以从 Evaluation 派生 Release Progress；课程可见性以 Catalog 和 Manifest 为准。
