# Day 29：完整链路验证与证据索引

返回：[课程目录](../README.md)

## 学习目标

- 将分散的局部检查连接成能复查的交付，而不是汇总一组“通过”。
- 任何“通过”都有与范围匹配的证据；缺少模型或数据库时不能声称完整系统通过。
- 一张行为到证据的完整矩阵和真实的剩余缺口。

## 先修与边界

先完成 Day 28 的关键产物；环境尚未满足时保留缺口，不跳过依赖验证。

本课围绕一个明确问题推进。项目版本与真实行为以固定源码、配置和运行结果为准；本教程的课文完整不代表学习者已经完成实验。

## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

每一层测试都有边界。浏览器证明用户操作，Go 测试证明处理逻辑，数据库/模型集成证明真实依赖行为。缺少其中一层时应保留缺口，而不是用另一层绿色结果代替。

## 动手步骤

1. 列出上传、问答、取消、失败、检索引用和 Eino 小服务的关键行为。
2. 为每项链接输入、版本、代码位置、测试命令及运行结果。
3. 重跑本轮修改包的验证；共享行为变化再扩大范围，记录既有失败。
4. 在真实 Chrome 复查涉及页面的对应操作，不使用隔离环境冒充登录态环境。
5. 检查日志与证据脱敏，区分已完成、受环境阻塞和未实施的内容。

## 观察与产出

任何“通过”都有与范围匹配的证据；缺少模型或数据库时不能声称完整系统通过。

交付：一张行为到证据的完整矩阵和真实的剩余缺口。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。

## 验证方式

检查每项产物的版本、源码位置与判断依据。本课不要求为了形式运行不相关的测试；引用前课验证时必须指明具体行为和结果。
