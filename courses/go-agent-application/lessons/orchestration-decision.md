## Node.js 对照

将 TypeScript 中的异步模型与工具调用映射到 Go 小接口、显式 error 和 context，避免把框架 SDK 类型扩散到业务层。

## 原理与机制

确定性工作流表达预先知道的步骤，Agent 选择依赖运行时判断，多 Agent 又增加通信、上下文和失败协调成本。应在同一任务集上比较质量、调用次数和可解释性，而不是因为框架支持就全部使用。

## 动手步骤

1. 选一个现有单 Agent 未能稳定完成的任务，记录失败条件。
2. 判断缺口是工具、上下文、数据，还是确实需要多角色协作；先排除局部缺陷。
3. 设计最小候选，可为顺序工作流或两个清晰职责；不必实现完整多 Agent 平台。
4. 用同一组输入比较现有方案和候选，记录模型/工具调用次数、耗时及正确性依据。
5. 若无可测收益，保留单 Agent 并记录决策；这也是合格成果。

## 检索问题

- 什么任务更适合固定工作流而不是自主循环？
