## Node.js 对照

从熟悉的页面请求、异步状态和错误处理出发；在 Go 中额外追踪显式 error、context 传播、接口边界与数据所有者。

## 原理与机制

测试要精确控制任务何时开始、何时阻塞、何时收到取消。channel 可以作为同步屏障，context 传递停止意图，有界等待防止失败测试永久卡住。检查返回错误还不够，还要确认被启动的工作结束。

## 动手步骤

1. 选择上一课定位的最小可测试边界，沿用已有接口注入阻塞模型或工具替身。
2. 用 started 信号确认调用已开始，再触发取消；不要用固定长 sleep 猜时机。
3. 在替身收到 ctx.Done 后报告退出，断言调用方与子任务都能在测试 deadline 内结束。
4. 验证取消返回的错误类别、终态次数，以及流/订阅的关闭责任。
5. 补一个正常完成对照，防止修复让全部请求都提前停止。

## 观察与产出

测试本身有超时保护；能区分调用方返回和底层工作退出。对独立后台任务按既有约定验证。

交付：正常与取消两组测试、失败前后输出及资源回收断言。

证据需能定位到当前版本与具体行为；观察事实和个人推断分别写清。
