# Agent 算法综合：可解释任务执行

## 算法映射

综合题不要求构建某个特定 Agent，而是把一个复杂任务拆成五层：检索负责候选证据，规划负责状态与动作，DAG 负责工具前置关系，调度负责容量与优先级，在线选择负责有限预算下的试探。每一层要输出可观察状态和有限失败回退，避免把不可解释的循环藏在单个大函数中。

TypeScript 主实现可先定义不可变任务描述和显式状态机；Go 对照时重点检查并发取消、队列所有权和共享映射访问。任何层都可以使用简单算法起步，复杂模型只有在数据与约束证明需要时才加入。

## 阶梯题组

### 简单恢复

- [#146 LRU 缓存](https://leetcode.cn/problems/lru-cache/)（证据缓存边界）。

### 经典模板（Hot 100 优先）

- [#239 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)（流式状态摘要）。
- [#743 网络延迟时间](https://leetcode.cn/problems/network-delay-time/)（动作代价传播）。

### 深入迁移

- [#295 数据流的中位数](https://leetcode.cn/problems/find-median-from-data-stream/)（持续状态与双结构协调）。

## 最终交付

选择一个虚拟任务，例如“检索三条证据后执行两个有依赖的工具调用”，写出状态、代价、候选截断、依赖图、队列规则和每层失败回退。只写模型与接口，不连接真实账号、外部工具或私有数据。

## 限时与复盘

简单恢复 20 分钟，经典模板每题 35 分钟，深入迁移 50 分钟。复盘问题：每一层是否有唯一算法职责，发生失败时是回退、重试、升级还是终止？
